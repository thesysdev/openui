---
title: Generate a dashboard
description: Create a dashboard from a title and a prompt with dashboards.create.
---

`dashboards.create()` builds a dashboard from a title and a prompt. Pass `{ stream: true }` so the dashboard shows while it's being built: the first response arrives as soon as the dashboard has an id, and the renderer shows it building, with its steps. The last arrives once the dashboard is saved. Return the last one to the model. See [Stream the build](#stream-the-build).

Without `stream`, the call resolves once the dashboard starts generating, after the model has checked your data, and the renderer streams the rest.

```ts
import { dashboards } from "@/lib/openui";

const response = await dashboards.create(
  {
    title: "Orders, last 30 days",
    prompt:
      "Daily orders and revenue for the last 30 days as a line chart, a KPI row with total revenue, " +
      "order count, and refund rate, and a table of the 10 largest orders. Add a status filter.",
  },
  { userId: session.user.id },
  { signal: request.signal },
);
```

| Parameter | Description                                                                          |
| --------- | ------------------------------------------------------------------------------------ |
| `title`   | A short title, shown in the renderer and the dashboard list.                         |
| `prompt`  | What to build: the sections, metrics, charts, and tables, and which data each shows. |

The second argument is the [context](/docs/dashboards/authentication#the-user-id). The dashboard belongs to `context.userId`, who can [share it](/docs/dashboards/sharing) later. The third is optional: `signal` cancels the call while it waits, and [`stream`](#stream-the-build) yields each response as it comes.

## The response

`create` resolves with a response string. Use it unchanged:

- **In an agent:** return it as the tool result. It gives the agent the dashboard's metadata, such as its id, which the agent uses to request edits later. See [Add to your agent](/docs/dashboards/add-to-your-agent).
- **In the browser:** pass it to `LiveArtifactRenderer` as `response`. See [Render a dashboard](/docs/dashboards/render).

## Stream the build

With `{ stream: true }`, `create` yields two responses: "Started…" as soon as the dashboard has an id, and "Created…" or "Couldn't…" once it's saved or failed. Pass each to the renderer. The agent gets the last one, which also tells you if the build failed. Use it when your agent framework streams tool output.

```ts
for await (const response of dashboards.create(
  { title, prompt },
  { userId: session.user.id },
  { stream: true, signal: request.signal },
)) {
  // pass each response to the renderer
}
```

The build runs inside the request that calls `create`, with `stream: true` until the dashboard is saved, so the route needs a timeout long enough for it. On Vercel, set it with `export const maxDuration = 300`. Other hosts have their own setting.

## Write the prompt

The model that builds the dashboard sees the prompt, the component library, and the data tools. It doesn't see the conversation that led to it.

- **Name the data:** Say which metrics, entities, and time ranges to show, so the model picks the right tools.
- **Describe the layout:** Mention the charts, tables, KPIs, and filters to include.
- **Leave out the numbers:** The dashboard loads them through data tools every time it opens.

For example, "revenue by plan for the last 90 days as a stacked bar chart, with a plan filter" builds a better dashboard than "a revenue dashboard".

## When generation finishes

The dashboard is saved when generation finishes. After that, it appears in the [dashboard list](/docs/dashboards/list) and can be [rendered](/docs/dashboards/render).

If generation fails, the renderer shows the error in its `Error` slot. Errors before generation starts reject the `create` call with an error that has a `code` and an HTTP `status`: an `OpenUIApiError`, or a `ToolExecutionError` for a missing `userId`.
