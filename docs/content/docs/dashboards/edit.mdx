---
title: Edit a dashboard
description: Change a saved dashboard in place with dashboards.edit.
---

`dashboards.edit()` changes a saved dashboard from a prompt that describes the change. It patches only the parts the prompt describes, and the rest of the dashboard stays as it is.

```ts
import { dashboards } from "@/lib/openui";

const response = await dashboards.edit(
  {
    id: dashboardId,
    prompt: "Add a pie chart of revenue by payment method next to the line chart.",
  },
  { userId: session.user.id },
  { signal: request.signal },
);
```

| Parameter | Description                                |
| --------- | ------------------------------------------ |
| `id`      | The dashboard's id.                        |
| `prompt`  | The change to make, and any data it needs. |

Only the dashboard's owner, and users it's [shared with](/docs/dashboards/sharing) to edit, can edit it. `context` says who's asking: `userId`, plus `groupIds` if you share with groups.

`edit` resolves with a response, like [`create`](/docs/dashboards/generate#the-response). Return it as the tool result, or pass it to the renderer.

## Get the id

The id comes from one of two places:

- **The tool result:** In a chat, the model reads the id from the earlier `create_dashboard` result and passes it to `edit_dashboard`. See [Add to your agent](/docs/dashboards/add-to-your-agent#add-the-edit-tool).
- **The list:** Each item from [`useArtifactList`](/docs/dashboards/list) has an `id`.

## Write the prompt

The model applies the change to the saved dashboard, so describe only what changes:

- "Add a table of failed payments below the chart."
- "Switch the revenue chart to weekly totals."
- "Remove the refunds section."

## What the user sees

1. The open dashboard stays on screen.
2. When the new version is ready, every renderer showing the dashboard switches to it, including renderers opened from the list.
3. The dashboard loads its data again for the new version.

## Two edits at once

A dashboard takes one change at a time. While an edit runs, including while the model calls your data tools, another `edit` of the same dashboard is rejected, not queued. It throws an `OpenUIApiError` with `status` 409, and the first edit carries on. The same happens while the dashboard is still being created.

For example, two users share a dashboard. One asks for a refunds chart, and a few seconds later the other asks to remove a section. The second `edit` throws at once, and its message says to try again in a minute. Return the message to the model, so it can tell the user:

```ts
import { OpenUIApiError } from "@openuidev/server";

try {
  return await dashboards.edit({ id, prompt }, { userId: session.user.id });
} catch (error) {
  if (error instanceof OpenUIApiError && error.status === 409) return error.message;
  throw error;
}
```

Once the first edit is saved, the user can ask again, and the second edit applies to the new version.

If an edit stops partway, such as when your server restarts during the model's tool calls, the dashboard is free again within 5 minutes. The user who started that edit can start a new one right away.
