Watch its database tool call, then see the dashboard appear as OpenUI Cloud streams the response. Ask “Now show Germany as a bar chart” to query a new scope using the conversation context.

This recipe uses the [UCI Online Retail dataset](https://archive.ics.uci.edu/dataset/352/online+retail): 541,909 real invoice lines from a UK retailer. The original download is public and licensed under CC BY 4.0.

## What you'll build

OpenUI Cloud calls a server-side `sales_dashboard` function through its [Gateway API](/docs/gateway/generate-openui-lang). The function validates the country and month, queries local SQLite, and returns real aggregates. Cloud uses those values to generate OpenUI Lang. Agent Interface displays the tool activity and renders the answer as it streams.

<Mermaid
  look="handDrawn"

  accTitle: Conversational analytics architecture

Conversation history is stored in OpenUI Cloud and remains available across page reloads and local server restarts.

Country and month are tool arguments selected from the question. Change them by asking a follow-up. This example has no interactive filter controls and no browser-side data queries.

## Run the example

You need Node.js 22.13 or newer, Python 3.9 or newer, and npm. The Python importer runs once; the app uses Node's built-in SQLite module.

```bash
git clone https://github.com/thesysdev/openui.git
cd openui/examples/cookbooks/conversational-analytics
npm ci

python3 -m venv .venv
source .venv/bin/activate
pip install -r scripts/requirements.txt
python scripts/prepare_data.py

npm run dev
```

On Windows, activate the environment with `.venv\Scripts\Activate.ps1` in PowerShell. Open [localhost:3000](http://localhost:3000). After configuring your Cloud key, ask **“Why did gross sales fall in February 2011?”**. Its tool result should show **£523,631.89** in gross sales and **1,100** orders.

To enable questions, create an inference key in the [Thesys Console](https://console.thesys.dev/keys), configure `THESYS_API_KEY` privately in the example's `.env.local`, then restart the app. The default model is `openai/gpt-5.5`; set `OPENUI_MODEL` to another supported [Gateway model](/docs/gateway/models) using its full `provider/model` identifier. Questions require the Cloud key and the imported dataset. Query and parser tests can run without model credentials.

## 1. Prepare and define the data

The importer downloads the original workbook, checks its SHA-256 checksum, and creates `data/retail.sqlite`. It also writes a manifest with source and exclusion counts. The archive, database, and generated files are ignored by Git.

Each source row is an **invoice line**, not an order. The fields used in this recipe are:

| Source field               | Use                                                      |
| -------------------------- | -------------------------------------------------------- |
| `InvoiceNo`                | Count distinct orders; identify C-prefixed cancellations |
| `StockCode`, `Description` | Group product and charge lines                           |
| `Quantity`, `UnitPrice`    | Calculate gross sales in GBP                             |
| `InvoiceDate`              | Select calendar months and daily chart buckets           |
| `Country`                  | Filter the transaction's country                         |

Define the metric before building the UI:

```text
Eligible line = invoice does not start with C
                AND Quantity > 0 AND UnitPrice > 0
Gross sales   = sum(Quantity × UnitPrice) for eligible lines
Orders        = count(distinct InvoiceNo) for eligible lines
Average order = gross sales / orders
```

The import retains **530,104 eligible lines**. It excludes 9,288 cancellation lines, 1,336 other non-positive-quantity lines, and 1,181 other non-positive-price lines. These exclusion categories are applied in that order and do not overlap.

Missing customer IDs do not disqualify a sale. Customer IDs are not imported, missing descriptions fall back to the stock code, and original duplicate lines remain. Positive-priced charges such as postage remain in the totals and product table. Monetary amounts are stored as integers in units of £0.0001 to preserve fractional-penny prices, then rounded for display.

<Callout title="Gross sales, not net revenue">
  Returns and cancellations are excluded, rather than deducted. An order that is later canceled can
  still contribute its original positive line. Large orders can therefore dominate the comparison.
  Use these numbers to explain the chosen gross-sales definition; extend the accounting rules before
  reporting net revenue or profit.
</Callout>

The source covers December 1, 2010 through December 9, 2011. The app allows **January through November 2011**, using December 2010 as the first comparison baseline. It excludes the incomplete final December. Comparisons use whole calendar months, which have different lengths; they are not adjusted for trading days or seasonality.

See [prepare_data.py](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/scripts/prepare_data.py) for the complete import.

## 2. Expose one read-only query

Give the model one narrow function tool named `sales_dashboard`. Its arguments are a supported month and a country from the dataset:

```json
{ "month": "2011-02", "country": "Germany" }
```

The server validates these arguments and executes parameterized SQL against a read-only database connection. The model never sends executable SQL. This keeps natural-language requests within the supported analytics workflow.

For example, the country-scoped totals query binds every value:

```ts
const totals = db
  .prepare(
    `
  SELECT COALESCE(SUM(sales_units), 0) AS sales,
         COUNT(DISTINCT invoice) AS orders,
         COALESCE(SUM(quantity), 0) AS units
  FROM sales
  WHERE day >= ? AND day < ? AND country = ?
`,
  )
  .get(start, end, country);
```

The query calculates current and previous totals, fills missing chart days with zero, and compares the union of stock codes in both months. Including both months means a product whose sales disappear still appears in the comparison. It returns the ten smallest current-minus-previous differences, which are not a complete reconciliation of the overall change.

It also returns formatted display strings and a factual summary derived from the query. Cloud receives those strings together with the aggregates, so its answer can explain the actual query result.

The implementation lives in [analytics.ts](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/analytics.ts) and [the function tool](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/sales-tool.ts).

## 3. Choose the components

Start with the built-in library. This dashboard needs layout, cards, text, charts, and a table:

```ts title="src/library.ts"
import { createLibrary } from "@openuidev/react-lang";
import { openuiLibrary } from "@openuidev/react-ui/genui-lib";

export const library = createLibrary({
  root: "Stack",
  components: [
    "Stack",
    "Card",
    "CardHeader",
    "TextContent",
    "LineChart",
    "BarChart",
    "Series",
    "Table",
    "Col",
  ].map((name) => openuiLibrary.components[name]),
});
```

Generate the server specification from that same library:

```bash
npm run generate
```

The script uses `openui generate src/library.ts --spec --out src/generated/spec.json`. It also runs before development, builds, and verification. The example pins the published OpenUI packages so the renderer and generated signatures agree.

## 4. Declare and execute the analytics tool

A Responses function tool gives the model a typed interface to the query. Its JSON schema limits the month and country to the dataset's supported values:

```ts title="src/lib/sales-tool.ts"
export function salesDashboardTool(countries: string[]) {
  return {
    type: "function" as const,
    name: "sales_dashboard",
    description: "Query retail sales, the prior month, daily trends, and product changes.",
    parameters: {
      type: "object",
      properties: {
        month: { type: "string", enum: months },
        country: { type: "string", enum: countries },
      },
      required: ["month", "country"],
      additionalProperties: false,
    },
    strict: true,
  };
}
```

The model requests the tool; your server executes it. Validate the arguments again before touching SQLite, even though the model received a schema:

```ts
export async function executeSalesDashboard(argsJson: string) {
  const args = salesQuerySchema.parse(JSON.parse(argsJson));
  const db = openDatabase();
  try {
    return JSON.stringify(queryDashboard(db, args));
  } finally {
    db.close();
  }
}
```

The complete [executor](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/sales-tool.ts) also handles cancellation and includes the dataset, query arguments, and elapsed time in its result. Agent Interface's **Behind the scenes** timeline lets readers inspect the actual function arguments and output.

## 5. Connect Agent Interface and Cloud history

Agent Interface provides the sidebar, composer, tool timeline, loading state, and stop control. Connect generation to the local chat route, sending only the latest user message. Cloud restores the earlier context from the conversation id:

```ts title="src/lib/chat-client.ts"
const chatLLM: ChatLLM = {
  streamProtocol: openAIResponsesAdapter(),
  send: ({ threadId, messages, signal }) =>
    fetch("/api/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        threadId,
        input: openAIConversationMessageFormat.toApi(messages.slice(-1)),
      }),
      signal,
    }),
};
```

The server accepts exactly one bounded user-text item. It rejects browser-submitted history, system messages, and function outputs. Tool execution and conversation history stay on the server.

Use the published Cloud storage hook for the sidebar and saved messages:

```tsx title="src/components/retail-chat.tsx"
const storage = useOpenuiCloudStorage({
  token: "/api/frontend-token",
  features: { artifact: false },
});

<AgentInterface
  llm={chatLLM}
  storage={storage}
  componentLibrary={library}
  components={{ AssistantMessage: DashboardMessage }}
  agentName="Data analyst"
  theme={{ mode: "light" }}
>
  <AgentInterface.Welcome
    title="Explore your data through conversation"
    description="Turn questions into charts, comparisons, and clear answers. Follow up to explore a different angle."
  />
  <AgentInterface.Composer placeholder="Ask a question about your data…" />
</AgentInterface>;
```

`useOpenuiCloudStorage` is exported by the pinned `@openuidev/react-ui` package. It creates and loads conversations directly from Cloud using a short-lived frontend token. The [token route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/frontend-token/route.ts) mints that token with a stable server-owned `user_id` and `app_id`; the master key stays on the server. Generation verifies the conversation belongs to that same scope before using it.

The local defaults are `DEMO_USER_ID=local-demo` and `APP_ID=conversational-analytics-cookbook`. Keep these values stable so reloads and server restarts show the same conversations. Use a different app id for an independent copy.

The [full chat component](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/components/retail-chat.tsx) adds concrete starter questions. Source attribution sits below generated answers. Agent Interface owns the theme; the [layout](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/layout.tsx) imports its styles once.

The assistant-message override is small: it removes Cloud's content envelope and any opening code fence as soon as it arrives, then passes the growing program to `Renderer`:

```tsx
<Renderer
  response={extractProgram(message.content ?? "")}
  library={library}
  isStreaming={isStreaming}
/>
```

Do not wait for a closing code fence or the complete response. OpenUI can render resolved components while later definitions are still streaming. The [dashboard message](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/components/dashboard-message.tsx) also shows rendering errors and lets readers inspect the generated source. It contains no data-query handler or filter state.

## 6. Continue Cloud generation after tool execution

Generate the Cloud instructions with `generateSystemPrompt({ cloud: true, library: spec, promptOptions })`. The component specification matches the client library, and supported `additionalRules` explain the dataset and function tool. The [prompt](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/prompt.ts) requires a database call before a supported analytics answer, `root` first in the generated program, and values taken from the tool result. An illustrative layout supplies syntax guidance, not real financial data.

```ts
const cloud = new OpenAI({
  apiKey: process.env.THESYS_API_KEY,
  baseURL: "https://api.thesys.dev/v1/embed",
  timeout: 60000,
  maxRetries: 0,
});
const createParams = {
  model: process.env.OPENUI_MODEL || "openai/gpt-5.5",
  instructions: dashboardPrompt(countries),
  input: body.input,
  conversation: body.threadId,
  tools: [salesDashboardTool(countries)],
  store: true,
  max_output_tokens: 6000,
};
```

A function call is only the first model round. The server must execute it, send a `function_call_output` with the matching `call_id`, and continue generation. The example uses the OpenUI Cloud template's function-tool loop with `conversation: threadId` and `store: true`:

```ts
await runFunctionToolLoop({
  client: cloud,
  createParams,
  firstStream,
  tools: { sales_dashboard: executeSalesDashboard },
  enqueue,
  signal: abort.signal,
  maxRounds: 3,
});
```

The loop forwards tool calls, tool outputs, and text deltas as Responses Server-Sent Events. For each continuation, it sends only new function outputs to the same conversation. Cloud already holds the question and completed response items, so replaying them would duplicate history. It executes only declared app tools and skips calls already answered by Cloud. Tool errors become outputs the model can explain; incomplete provider streams become visible chat errors. The final allowed round settles its outstanding calls with further tool requests disabled.

The [chat route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/chat/route.ts) opens the first Cloud response inside the outgoing stream, so headers flush immediately. [Stream forwarding](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/cloud-stream.ts) disables proxy buffering and propagates the browser's stop signal through the [tool loop](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/tool-loop.ts).

Cloud returns a data-backed program with literal values and chart arrays. A follow-up such as **“Now show Germany as a bar chart”** triggers a fresh database call and streams a new answer. The model uses the conversation to retain February 2011. No filter widgets or runtime `Query` expressions are involved.

## 7. Handle incomplete and empty states

| State                               | Example behavior                                                           |
| ----------------------------------- | -------------------------------------------------------------------------- |
| Dataset not imported                | The chat error explains how to prepare it                                  |
| Database tool running               | Agent Interface shows tool activity                                        |
| Answer streaming                    | Resolved UI appears while later components arrive                          |
| No sales in the requested scope     | Zero-valued metrics and an explanation; ask about another month or country |
| Invalid tool arguments              | Validation rejects the query and returns a tool error                      |
| No Cloud key                        | Setup guidance appears in the chat                                         |
| Provider error or incomplete stream | Explicit error; connection closure alone is not treated as completion      |
| User stops generation               | The browser abort propagates to Cloud and prevents further tool execution  |
| Invalid generated components        | A visible rendering error asks the reader to retry                         |

The local example binds to loopback and uses a single demo identity. Its chat and token routes are disabled in production. Before deployment, replace that guard with server-side authentication and rate limits on both routes, derive `user_id` from the signed-in session, retain conversation ownership checks, authorize private replacement datasets, and provide persistent storage for SQLite.

## Verify the experience

Run the build, parser, query, stream, importer, and real-data checks:

```bash
npm run verify
python -m unittest discover -s scripts -p 'test_*.py'
npm run verify:data
```

`verify` does not require model credentials or the dataset. `verify:data` requires the completed import and checks these independently reproducible totals:

| February 2011 scope | Gross sales | Orders | January gross sales |
| ------------------- | ----------: | -----: | ------------------: |
| All countries       | £523,631.89 |  1,100 |         £691,364.56 |
| Germany             |   £9,581.05 |     19 |          £16,910.84 |

In the browser:

1. Ask **“Why did gross sales fall in February 2011?”**. Expand **Behind the scenes** and the `sales_dashboard` row to inspect its month, country, and returned aggregates.
2. Confirm metric cards appear while the response is still generating, before the full table is complete.
3. Ask **“Now show Germany as a bar chart.”** Confirm a new tool call uses Germany and February 2011, and the answer matches the Germany totals above.
4. Ask **“Show Saudi Arabia in April 2011.”** The answer should explain that there are no eligible sales.
5. Stop a generation, then ask another question to confirm recovery.
6. Switch to **New Chat** and reopen the previous conversation. Reload the page and restart the local server, then reopen the conversation from the sidebar. Its messages, dashboard, and tool activity should still be available.

Generated layouts can vary. The tool's arguments and returned values are the source for checking each answer.

For the default comparison, orders rise from 1,086 to 1,100 while average order value falls from £636.62 to £476.03. That describes the change; it does not establish a cause. The table's largest negative difference is a £77,183.60 January contribution from stock code `23166` with no February sales. Investigating such outliers and their cancellations is a separate analysis, especially before interpreting gross sales as revenue.
