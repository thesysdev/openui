Build a sales assistant with Agent Interface that answers “Why did gross sales fall in February 2011?” with metric cards, a daily trend, and a product comparison. Change the country or month and the dashboard queries the database again. Ask “Now show Germany as a bar chart” to generate a new view with the current context.

This recipe uses the [UCI Online Retail dataset](https://archive.ics.uci.edu/dataset/352/online+retail): 541,909 real invoice lines from a UK retailer. The original download is public and licensed under CC BY 4.0.

## What you'll build

OpenUI Cloud generates a layout and query arguments in OpenUI Lang through its [Gateway API](/docs/gateway/generate-openui-lang). The request includes the component library so Cloud can validate the generated interface. Agent Interface provides the conversation sidebar, composer, streaming lifecycle, and stop controls. A custom assistant message renders the dashboard and connects its reactive queries to a server-owned analytics endpoint.

There are two ways to explore the example:

- **Example dashboard:** open the reference conversation from the toolbar or sidebar. It contains a checked-in OpenUI Lang layout that queries the real database. No model credentials are needed.
- **Ask a question:** OpenUI Cloud generates and streams a fresh layout. The Cloud key stays on the server.

Both use the same renderer, component library, and analytics endpoint. The example dashboard is explicitly labeled; it does not simulate an AI response.

## Run the example

You need Node.js 22.13 or newer, Python 3.9 or newer, and npm. The Python importer runs once; the app uses Node's built-in SQLite module.

```bash
git clone https://github.com/thesysdev/openui.git
cd openui/examples/cookbooks/conversational-analytics
npm ci

python3 -m venv .venv
source .venv/bin/activate
pip install -r scripts/requirements.txt
python scripts/prepare_data.py

npm run dev
```

On Windows, activate the environment with `.venv\Scripts\Activate.ps1` in PowerShell. Open [localhost:3000](http://localhost:3000). Click **Example dashboard**. It should show **£523,631.89** in gross sales and **1,100** orders for February 2011.

To enable questions, create an inference key in the [Thesys Console](https://console.thesys.dev/keys), configure `THESYS_API_KEY` privately in the example's `.env.local`, then restart the app. The default model is `openai/gpt-5.5`; set `OPENUI_MODEL` to another supported [Gateway model](/docs/gateway/models) using its full `provider/model` identifier. The example works without a Cloud key until you submit a question.

## 1. Prepare and define the data

The importer downloads the original workbook, checks its SHA-256 checksum, and creates `data/retail.sqlite`. It also writes a manifest with source and exclusion counts. The archive, database, and generated files are ignored by Git.

Each source row is an **invoice line**, not an order. The fields used in this recipe are:

| Source field               | Use                                                      |
| -------------------------- | -------------------------------------------------------- |
| `InvoiceNo`                | Count distinct orders; identify C-prefixed cancellations |
| `StockCode`, `Description` | Group product and charge lines                           |
| `Quantity`, `UnitPrice`    | Calculate gross sales in GBP                             |
| `InvoiceDate`              | Select calendar months and daily chart buckets           |
| `Country`                  | Filter the transaction's country                         |

Define the metric before building the UI:

```text
Eligible line = invoice does not start with C
                AND Quantity > 0 AND UnitPrice > 0
Gross sales   = sum(Quantity × UnitPrice) for eligible lines
Orders        = count(distinct InvoiceNo) for eligible lines
Average order = gross sales / orders
```

The import retains **530,104 eligible lines**. It excludes 9,288 cancellation lines, 1,336 other non-positive-quantity lines, and 1,181 other non-positive-price lines. These exclusion categories are applied in that order and do not overlap.

Missing customer IDs do not disqualify a sale. Customer IDs are not imported, missing descriptions fall back to the stock code, and original duplicate lines remain. Positive-priced charges such as postage remain in the totals and product table. Monetary amounts are stored as integers in units of £0.0001 to preserve fractional-penny prices, then rounded for display.

<Callout title="Gross sales, not net revenue">
  Returns and cancellations are excluded, rather than deducted. An order that is later canceled can
  still contribute its original positive line. Large orders can therefore dominate the comparison.
  Use these numbers to explain the chosen gross-sales definition; extend the accounting rules before
  reporting net revenue or profit.
</Callout>

The source covers December 1, 2010 through December 9, 2011. The app allows **January through November 2011**, using December 2010 as the first comparison baseline. It excludes the incomplete final December. Comparisons use whole calendar months, which have different lengths; they are not adjusted for trading days or seasonality.

See [prepare_data.py](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/scripts/prepare_data.py) for the complete import.

## 2. Expose one read-only query

Give OpenUI a narrow tool named `sales_dashboard`. Its arguments are a supported month and a country from the dataset:

```json
{ "month": "2011-02", "country": "Germany" }
```

The server validates these arguments and executes parameterized SQL against a read-only database connection. The model never sends executable SQL. This keeps natural-language requests within the supported analytics workflow.

For example, the country-scoped totals query binds every value:

```ts
const totals = db
  .prepare(
    `
  SELECT COALESCE(SUM(sales_units), 0) AS sales,
         COUNT(DISTINCT invoice) AS orders,
         COALESCE(SUM(quantity), 0) AS units
  FROM sales
  WHERE day >= ? AND day < ? AND country = ?
`,
  )
  .get(start, end, country);
```

The endpoint calculates current and previous totals, fills missing chart days with zero, and compares the union of stock codes in both months. Including both months means a product whose sales disappear still appears in the comparison. It returns the ten smallest current-minus-previous differences, which are not a complete reconciliation of the overall change.

It also returns formatted display strings and a factual summary derived from the query. Keeping these in the result means the explanation updates along with the charts when a filter changes.

The implementation lives in [analytics.ts](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/analytics.ts) and [the analytics route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/analytics/route.ts).

## 3. Choose the components

Start with the built-in library. This dashboard needs layout, cards, text, charts, a table, and two selects:

```ts title="src/library.ts"
import { createLibrary } from "@openuidev/react-lang";
import { openuiLibrary } from "@openuidev/react-ui/genui-lib";

export const library = createLibrary({
  root: "Stack",
  components: [
    "Stack",
    "Card",
    "CardHeader",
    "TextContent",
    "LineChart",
    "BarChart",
    "Series",
    "Table",
    "Col",
    "Select",
    "SelectItem",
  ].map((name) => openuiLibrary.components[name]),
});
```

Generate the server specification from that same library:

```bash
npm run generate
```

The script uses `openui generate src/library.ts --spec --out src/generated/spec.json`. It also runs before development, builds, and verification. The example pins the published OpenUI packages so the renderer and generated signatures agree.

## 4. Bind a query to reactive filters

In OpenUI Lang, `$country` and `$month` hold the selected values. Use them in both the selects and the query arguments. This small program shows the connection:

```text
root = Stack([filters, content], "column", "l")
$country = "All countries"
$month = "2011-02"
data = Query("sales_dashboard", {country: $country, month: $month}, {ready: false, countries: []})
countries = @Each(data.countries, "country", SelectItem(country, country))
countryFilter = Select("country", countries, "Country", null, $country)
monthFilter = Select("month", [SelectItem("2011-01", "January"), SelectItem("2011-02", "February")], "Month", null, $month)
filters = Stack([countryFilter, monthFilter], "row", "m")
content = data.ready ? results : TextContent("Loading sales data…")
results = Stack([metric, TextContent(data.summary), details], "column", "l")
metric = Card([TextContent("Gross sales", "small"), TextContent(data.sales, "large-heavy")])
details = data.empty ? TextContent("Choose another country or month.") : chart
chart = LineChart(data.trend.day, [Series("Gross sales (GBP)", data.trend.sales)])
```

`Query` starts with its fallback object while the request runs. Once data arrives, `data.ready` reveals the results. Array plucking, such as `data.trend.day`, feeds the chart's column arrays. The full [example program](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/example-program.ts) adds all supported months, three metric cards, and the product table.

In this library, the `Select` binding is its **fifth argument**: name, items, placeholder, validation rules, value. Using a `$` variable there is what connects the control to the query.

## 5. Put the dashboard inside Agent Interface

Use Agent Interface for the chat shell. Pass the shared library, the Cloud transport, and session storage, then override only the assistant message to connect the dashboard's queries:

```tsx title="src/components/retail-chat.tsx"
const theme: ThemeProps = { mode: "light" };

export default function RetailChat() {
  const [session] = useState(createChatSession);
  const components = useMemo<AgentInterfaceComponents>(
    () => ({
      AssistantMessage: (props) => <DashboardMessage {...props} session={session} />,
    }),
    [session],
  );

  return (
    <AgentInterface
      llm={session.llm}
      storage={session.storage}
      componentLibrary={library}
      components={components}
      agentName="Retail analyst"
      theme={theme}
    >
      <AgentInterface.Welcome title="Explore retail sales" />
      <AgentInterface.Composer placeholder="Ask about sales…" />
      <SessionSync session={session} />
    </AgentInterface>
  );
}
```

`SessionSync` saves the current messages to the in-memory storage adapter when they change. The complete [chat component](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/components/retail-chat.tsx) adds starter questions, reference-dashboard navigation, and source links. Agent Interface owns the theme; the [layout](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/layout.tsx) imports its styles once.

Inside `DashboardMessage`, keep the tool provider stable and map `sales_dashboard` to the analytics route:

```tsx
const toolProvider = useMemo(
  () => ({
    sales_dashboard: async (args: Record<string, unknown>) => {
      const response = await fetch("/api/analytics", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(args),
      });
      const data = await response.json();
      if (!response.ok) throw new Error(data.error);
      return data;
    },
  }),
  [],
);

<Renderer
  response={extractProgram(message.content ?? "")}
  library={library}
  toolProvider={toolProvider}
  isStreaming={isStreaming}
  initialState={initialState}
  onStateUpdate={saveFilters}
  queryLoader={<p role="status">Refreshing sales data…</p>}
/>;
```

`extractProgram` reads the OpenUI Lang from Cloud's content envelope. The full [dashboard message](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/components/dashboard-message.tsx) validates and saves `$country` and `$month` under the message ID, restores them when a conversation is reopened, and provides query-error recovery and source inspection.

Changing the country updates `$country`, which changes the query arguments. OpenUI runs `sales_dashboard` again and refreshes every dependent component. **Filter changes do not call the model.**

## 6. Generate and stream with OpenUI Cloud

The chat route sends the generated library specification through `generateSystemPrompt({ cloud: true, library: spec, promptOptions })`. With `cloud: true`, this produces Cloud's managed configuration block containing the schema and supported prompt options. Cloud assembles the generation instructions and validates output against that library.

Use `additionalRules` to explain the reactive query contract and `examples` to supply the working dashboard. These are supported Cloud options; the local prompt flags `toolCalls`, `bindings`, and `toolExamples` are not sent in the Cloud configuration.

`sales_dashboard` remains an OpenUI `Query` expression executed through the renderer's `toolProvider`. It is not a Responses function tool. Cloud generates the expression, then the browser asks the local analytics route for the values. SQLite stays in the application.

The [prompt](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/prompt.ts) asks the model to:

- Generate a complete OpenUI Lang program with `root` first.
- Use only the supported tool, countries, months, and result fields.
- Read all financial values and the explanatory summary from the query result.
- Preserve current filters on follow-ups unless the question changes them.
- Explain unsupported questions instead of inventing data or silently changing dates.

The server uses the OpenAI-compatible SDK to call OpenUI Cloud's Responses endpoint. Both the server credential and endpoint are set explicitly:

```ts
import OpenAI from "openai";

const cloud = new OpenAI({
  apiKey: process.env.THESYS_API_KEY,
  baseURL: "https://api.thesys.dev/v1/embed",
  timeout: 60000,
  maxRetries: 0,
});

const upstream = await cloud.responses.create(
  {
    model: process.env.OPENUI_MODEL || "openai/gpt-5.5",
    instructions: dashboardPrompt(countries),
    input: cloudInput(body, countries),
    stream: true,
    store: false,
    max_output_tokens: 6000,
  },
  { signal: abort.signal },
);
```

`cloudInput` validates the latest dashboard's filters and includes them alongside the conversation's user and assistant messages. The route forwards Responses events as Server-Sent Events. Connect them to Agent Interface using its published adapter:

```ts title="src/lib/chat-session.ts"
const llm = fetchLLM({
  url: "/api/chat",
  streamAdapter: openAIResponsesAdapter(),
  messageFormat: {
    ...identityMessageFormat,
    toApi: serializeMessages,
  },
});
```

The example's serializer sends up to 12 non-empty user and assistant messages, attaching saved filters to each dashboard message. Agent Interface consumes the stream and updates the assistant message as OpenUI Lang arrives. The server forwards cancellation to Cloud and reports an error if the upstream stream ends without completion, fails, or refuses the request. See the [chat route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/chat/route.ts), [stream forwarding](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/cloud-stream.ts), and [Gateway Responses reference](/docs/gateway/api/responses).

Each assistant message has its own renderer and filter state. A follow-up uses the latest dashboard's current country and month unless the question changes them. The [session adapter](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/chat-session.ts) keeps conversations in memory, so switching threads preserves their messages and filters; reloading the page clears them. Cloud generation uses `store: false`. See the [Conversations API](/docs/gateway/api/conversations) to add persisted Cloud threads.

## 7. Handle incomplete and empty states

| State                                      | Example behavior                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| Dataset not imported                       | Visible preparation instructions and a retry button                      |
| Query running                              | Loading indicator while OpenUI fetches the result                        |
| No sales for the selected country/month    | Zero-valued metrics, explanatory text, and filters to recover            |
| Unsupported arguments                      | Server returns HTTP 400; no arbitrary SQL executes                       |
| No Cloud key                               | The question shows setup guidance; the existing dashboard remains usable |
| Model error, refusal, or incomplete stream | Explicit error; no completion is inferred from a closed connection       |
| User stops generation                      | Agent Interface stops the request; the browser abort propagates to Cloud |
| Invalid generated components               | Renderer errors appear with a way to load the example again              |

The local example binds to loopback. If you deploy it, add authentication and rate limits to the model route, authorize access to any private replacement dataset, and provide persistent storage for SQLite. The sample has no hosted database or production identity layer.

## Verify the experience

Run the build, parser, query, stream, importer, and real-data checks:

```bash
npm run verify
python -m unittest discover -s scripts -p 'test_*.py'
npm run verify:data
```

`verify` does not require model credentials or the dataset. `verify:data` requires the completed import and checks these independently reproducible totals:

| February 2011 filter | Gross sales | Orders | January gross sales |
| -------------------- | ----------: | -----: | ------------------: |
| All countries        | £523,631.89 |  1,100 |         £691,364.56 |
| Germany              |   £9,581.05 |     19 |          £16,910.84 |

In the browser:

1. Click **Example dashboard** and check the all-country totals.
2. Select **Germany**. The metrics, chart, and table should refresh without generating a new layout.
3. Start a **New Chat**, then reopen **Example dashboard** from the sidebar. Germany and its totals should be preserved.
4. Select **Saudi Arabia** and **2011-04**. The page should explain that there are no eligible sales.
5. With a configured key, ask **“Why did gross sales fall in February 2011?”**, then **“Now show Germany as a bar chart.”** Check the new layout against the same query totals; model layouts can vary.
6. Stop a generation using Agent Interface, then open **Example dashboard** to confirm recovery.

For the default comparison, orders rise from 1,086 to 1,100 while average order value falls from £636.62 to £476.03. That describes the change; it does not establish a cause. The table's largest negative difference is a £77,183.60 January contribution from stock code `23166` with no February sales. Investigating such outliers and their cancellations is a separate analysis, especially before interpreting gross sales as revenue.
