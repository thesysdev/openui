Build an assistant that queries data and chooses a useful way to present the answer. Ask for a ranking, compare two drivers in a chart, then narrow the comparison with a follow-up. Agent Interface shows the tool call while OpenUI Cloud streams the visual response.

This recipe uses recorded lap times from the **2024 Miami Grand Prix**, provided by [OpenF1](https://openf1.org/docs/). Each record is a driver's time for one lap, measured in seconds.

## What you'll build

<CookbookAnalyticsFlow />

Try this conversation:

1. **“Which five drivers set the fastest laps in Miami?”** Get a ranked table.
2. **“Compare Norris and Verstappen lap by lap.”** See their times in a line chart.
3. **“Focus on their final ten laps.”** Narrow the chart while retaining the selected drivers.

Conversation history is stored in OpenUI Cloud and remains available across page reloads and local server restarts.

## Run the example

You need Node.js 22.13 or newer and npm.

```bash
git clone https://github.com/thesysdev/openui.git
cd openui/examples/cookbooks/conversational-analytics
npm ci
npm run prepare:data
```

Create an inference key in the [Thesys Console](https://console.thesys.dev/keys) and configure `THESYS_API_KEY` privately in the example's `.env.local`. Then start the app:

```bash
npm run dev
```

Open [localhost:3000](http://localhost:3000) and try a starter question. The default model is `openai/gpt-5.5`; use `OPENUI_MODEL` to select another supported [Gateway model](/docs/gateway/models).

## 1. Prepare the data

`npm run prepare:data` downloads the race's drivers and lap times from OpenF1 and creates `data/race.sqlite`. It runs once; subsequent questions query the local database.

The example covers 20 drivers and 57 race laps. You can rank drivers by their fastest recorded lap or compare selected drivers over a lap range. See [prepare-data.ts](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/scripts/prepare-data.ts) for the importer.

## 2. Expose an analytics tool

Give Cloud a function tool named `query_race`. It accepts the question's scope as structured arguments:

```json
{
  "view": "lap_times",
  "driver_numbers": [4, 1],
  "lap_start": 48,
  "lap_end": 57,
  "limit": 5
}
```

These arguments compare Norris and Verstappen over the final ten laps. The other view, `fastest_laps`, ranks each driver's best time; `limit` controls the number of ranked drivers.

The [tool definition](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/race-tool.ts) declares both views, the available driver numbers, and the allowed lap range in its JSON schema. Your server validates the arguments and executes a read-only query:

```ts title="src/lib/race-tool.ts"
export async function executeRaceQuery(argsJson: string) {
  const args = raceQuerySchema.parse(JSON.parse(argsJson));
  const db = openDatabase();
  try {
    return JSON.stringify(queryRace(db, args));
  } finally {
    db.close();
  }
}
```

The result contains ranked lap times or aligned chart labels and series. Cloud uses those values to build the answer. The complete executor also returns the query arguments and elapsed time, which readers can inspect in Agent Interface's **Behind the scenes** timeline.

The [query implementation](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/analytics.ts) uses parameterized SQL. Missing times are left out of comparisons rather than plotted as zero.

## 3. Choose the components

Use a small selection from the built-in library:

```ts title="src/library.ts"
import { createLibrary } from "@openuidev/react-lang";
import { openuiLibrary } from "@openuidev/react-ui/genui-lib";

export const library = createLibrary({
  root: "Stack",
  components: [
    "Stack",
    "Card",
    "CardHeader",
    "TextContent",
    "LineChart",
    "BarChart",
    "Series",
    "Table",
    "Col",
  ].map((name) => openuiLibrary.components[name]),
});
```

Generate the server specification from the same library used by the renderer:

```bash
npm run generate
```

This runs `openui generate src/library.ts --spec --out src/generated/spec.json`. It also runs automatically before development and builds.

## 4. Connect Agent Interface and Cloud history

Agent Interface provides the sidebar, composer, tool timeline, and stop control. Connect generation to the local chat route, sending only the latest user message. Cloud restores the earlier context from the conversation id:

```ts title="src/lib/chat-client.ts"
const chatLLM: ChatLLM = {
  streamProtocol: openAIResponsesAdapter(),
  send: ({ threadId, messages, signal }) =>
    fetch("/api/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        threadId,
        input: openAIConversationMessageFormat.toApi(messages.slice(-1)),
      }),
      signal,
    }),
};
```

Use the Cloud storage hook for the sidebar and saved messages:

```tsx title="src/components/analytics-chat.tsx"
const storage = useOpenuiCloudStorage({
  token: "/api/frontend-token",
  features: { artifact: false },
});

<AgentInterface
  llm={chatLLM}
  storage={storage}
  componentLibrary={library}
  components={{ AssistantMessage: AnalyticsMessage }}
  agentName="Data analyst"
  theme={{ mode: "light" }}
>
  <AgentInterface.Welcome
    title="Explore your data through conversation"
    description="Turn questions into charts, comparisons, and clear answers. Follow up to explore a different angle."
  />
  <AgentInterface.Composer placeholder="Ask a question about your data…" />
</AgentInterface>;
```

`useOpenuiCloudStorage` is exported by the example's pinned `@openuidev/react-ui` package. The [token route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/frontend-token/route.ts) issues a short-lived token for a stable `user_id` and `app_id`; the master key stays on the server. Generation checks that the conversation belongs to the same scope.

Keep `DEMO_USER_ID` and `APP_ID` stable to retain conversation history. Their defaults are `local-demo` and `conversational-analytics-cookbook`. Agent Interface owns the theme; [layout.tsx](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/layout.tsx) imports its styles once.

## 5. Stream the tool call and visual answer

The [prompt](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/prompt.ts) combines the generated component specification with the available drivers and instructions to call `query_race` before answering. It asks Cloud to choose a presentation that fits the question and use the returned values.

```ts title="src/app/api/chat/route.ts"
const cloud = new OpenAI({
  apiKey: process.env.THESYS_API_KEY,
  baseURL: "https://api.thesys.dev/v1/embed",
  timeout: 60000,
  maxRetries: 0,
});
const createParams = {
  model: process.env.OPENUI_MODEL || "openai/gpt-5.5",
  instructions: analyticsPrompt(drivers),
  input: body.input,
  conversation: body.threadId,
  tools: [raceQueryTool(drivers)],
  store: true,
  max_output_tokens: 6000,
};
```

When Cloud requests a function call, execute it and send its result back with the matching `call_id`. The example uses the OpenUI Cloud template's [function-tool loop](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/tool-loop.ts):

```ts
await runFunctionToolLoop({
  client: cloud,
  createParams,
  firstStream,
  tools: { query_race: executeRaceQuery },
  enqueue,
  signal: abort.signal,
  maxRounds: 3,
});
```

The loop forwards tool activity and text deltas as Responses Server-Sent Events. Each continuation sends only the new tool outputs to the saved conversation. Cloud already holds the preceding question and response items.

The [chat route](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/app/api/chat/route.ts) flushes response headers immediately. Its [stream forwarding](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/lib/cloud-stream.ts) propagates cancellation and reports tool or provider errors.

The [assistant-message component](https://github.com/thesysdev/openui/blob/main/examples/cookbooks/conversational-analytics/src/components/analytics-message.tsx) removes Cloud's content envelope and passes the growing OpenUI Lang program to the renderer:

```tsx
<Renderer
  response={extractProgram(message.content ?? "")}
  library={library}
  isStreaming={isStreaming}
/>
```

The prompt emits `root` first, followed by its components in reading order. Resolved components can appear while the rest of the response is still arriving. If the response includes an opening code fence, remove it immediately rather than waiting for the closing fence.

A follow-up such as **“Focus on their final ten laps”** triggers a new tool call with the same drivers and laps 48 through 57. Cloud then streams the updated chart.

## Verify the experience

```bash
npm run verify
npm run verify:data
```

`verify` checks the queries, importer, tool streaming, conversation transport, component schema, and production build. `verify:data` checks the downloaded race snapshot, including Oscar Piastri's **1:30.634** lap and the Norris/Verstappen comparison.

In the browser:

1. Ask for the five fastest drivers. Expand **Behind the scenes** to inspect `query_race` and its result.
2. Ask for the Norris/Verstappen comparison. Confirm the answer starts appearing while generation is still active.
3. Ask **“Focus on their final ten laps.”** Confirm the chart covers laps 48 through 57 and retains both drivers.
4. Stop a generation and ask another question to check recovery.
5. Reload the page or restart the server. Reopen the conversation from the sidebar and confirm its messages, visual answers, and tool activity are retained.

Generated layouts can vary. Check values against the tool result. Missing data and tool errors should produce an explanation rather than invented points.

## Connect your own data

Replace `queryRace` with a query to your database or API. Update the tool's arguments and description, then add any components your answers need to `src/library.ts` and regenerate the specification.

This example runs locally with a single demo identity. Before deploying it, replace the local guard with authentication and rate limits, derive user identity from the signed-in session, and retain conversation ownership checks.
