---
title: Action Expressions
description: One step on its own, several steps in Action([...]), and action props in your components.
---

An action is what runs when the user clicks: send a message to the model, open a link, change state, run a mutation, or run a [custom action](/docs/openui-lang/custom-actions). The model writes it as one or more `@` steps, and a component receives it through an action prop.

## One step

A single step needs no wrapper:

```text
askBtn = Button("Explain this chart", @ToAssistant("Explain the revenue chart"))
docsBtn = Button("Docs", @OpenUrl("https://example.com/docs"))
```

`@ToAssistant("...")` here is the same as `Action([@ToAssistant("...")])`.

## Several steps

Put several steps in `Action([...])`. They run in order:

```text
saveBtn = Button("Save", Action([@Run(createTicket), @Run(tickets), @Reset($title)]))
```

An action can be its own statement and be used in several places:

```text
onSave = Action([@Run(createTicket), @Run(tickets), @Reset($title)])
saveBtn = Button("Save", onSave)
```

An `Action([...])` inside another one is flattened into it.

A plain list of steps is not an action:

```text
saveBtn = Button("Save", [@Set($saved, true), @ToAssistant("Saved")])
```

The component receives a plain array, not one action, and no error is reported. A component that passes the prop to `triggerAction`, like the `Button` in `@openuidev/react-ui`, then treats the click as having no action and sends its label to the assistant. Write `Action([...])` for several steps.

## Steps

| Step                              | What it does                                                                                                       |
| :-------------------------------- | :----------------------------------------------------------------------------------------------------------------- |
| `@ToAssistant(message, context?)` | Sends a `continue_conversation` event with the message. `context` can be any value and reaches the host unchanged. |
| `@OpenUrl(url)`                   | Sends an `open_url` event with `params.url`.                                                                       |
| `@Set($var, value)`               | Sets a `$variable`. `value` is evaluated when the step runs.                                                       |
| `@Reset($a, $b, ...)`             | Restores `$variables` to their declared defaults.                                                                  |
| `@Run(ref)`                       | Runs a `Mutation` or fetches a `Query` again. A failed mutation stops the steps after it.                          |
| `@Name(...)`                      | A [custom action](/docs/openui-lang/custom-actions) from your library. Sends an event with `type: "Name"`.         |

The prompt lists `@Run` only when the `toolCalls` option is on, and `@Set` and `@Reset` only when `bindings` is on. See [Queries & Mutations](/docs/openui-lang/queries-mutations) and [Reactive State](/docs/openui-lang/reactive-state).

A step that cannot run does nothing, and the other steps still run. Examples are `@Run(x)` when there is no `Query` or `Mutation` named `x`, `@Reset("title")` without the `$`, and a custom action with any invalid argument.

### Context for `@ToAssistant`

The second argument of `@ToAssistant` is optional context: a string, number, object, or array. The host receives it unchanged in `event.params.context`:

```text
approveBtn = Button("Approve", @ToAssistant("Approve this order", {orderId: 42}))
```

```ts
{
  type: "continue_conversation",
  humanFriendlyMessage: "Approve this order",
  params: { context: { orderId: 42 } },
  formState: { /* ... */ },
  formName: undefined,
}
```

With no context, or `null`, `params` is `{}`. How the context reaches the model is up to the host. The chat in `@openuidev/react-ui` adds it to the stored user turn, after the form state. See [Storing Messages](/docs/openui-lang/messages#the-react-ui-chat-format).

## Action props in your components

Use `action()` for a prop that takes an action:

```tsx
import { action, defineComponent, useTriggerAction } from "@openuidev/react-lang";
import { z } from "zod/v4";

export const Button = defineComponent({
  name: "Button",
  description: "A clickable button",
  props: z.object({
    label: z.string(),
    action: action().optional(),
  }),
  component: ({ props }) => {
    const triggerAction = useTriggerAction();
    return (
      <button onClick={() => triggerAction(props.label, undefined, props.action)}>
        {props.label}
      </button>
    );
  },
});
```

`action()` returns a schema tagged `ActionExpression`. It is the same schema on every call. In the generated prompt, the prop prints as:

```text
Button(label: string, action?: ActionExpression)
```

When any component has an `ActionExpression` prop, the prompt also explains that such a prop takes one step or `Action([...])`, and adds an Action section that lists the available steps, including your custom actions.

In the JSON Schema from `library.toJSONSchema()`, the prop is a reference, like a component slot:

```json
{ "action": { "$ref": "#/$defs/ActionExpression" } }
```

The `ActionExpression` entry in `$defs` describes the legacy action objects (`{type: "open_url", url}`, `{type: "continue_conversation", context?}`, and `{type, params?}`). Those objects still work.

At runtime the prop holds an evaluated plan, `{ steps: [...] }`. Pass it to `triggerAction(label, formName, action)`, which runs the steps in order and sends events to `onAction`. When the prop is empty, `triggerAction(label)` sends a `continue_conversation` event with the label as the message.

`action()` replaces the older `tagSchemaId(z.any(), "ActionExpression")` pattern. That pattern still gives the same prompt signature, but its JSON Schema is `{}` instead of the `$ref`.

## Slots that take only some actions

A prop can name the steps it accepts. Build it from the `.ref` of a custom action and the built-in step refs in `steps`:

```tsx
import { defineAction, defineComponent, steps, useTriggerAction } from "@openuidev/react-lang";
import { z } from "zod/v4";

const copyToClipboard = defineAction({
  name: "CopyToClipboard",
  description: "Copies text to the clipboard",
  params: z.object({ text: z.string() }),
});

const ShareButton = defineComponent({
  name: "ShareButton",
  description: "Shares a link or copies it",
  props: z.object({
    label: z.string(),
    share: z.union([copyToClipboard.ref, steps.OpenUrl.ref]),
  }),
  component: ({ props }) => {
    const triggerAction = useTriggerAction();
    return (
      <button onClick={() => triggerAction(props.label, undefined, props.share)}>
        {props.label}
      </button>
    );
  },
});
```

The prompt prints the prop with the step names, and adds a line saying such a prop accepts only the steps listed:

```text
ShareButton(label: string, share: @CopyToClipboard | @OpenUrl)
```

In the JSON Schema, the prop is an `anyOf` of `{"$ref": "#/$defs/CopyToClipboard"}` and `{"$ref": "#/$defs/OpenUrl"}`, and `$defs` has an entry for each. `steps` has refs for `OpenUrl` and `ToAssistant`.

<Callout type="warn">
  Restricted slots are not enforced yet. They shape the prompt and the JSON Schema only. At runtime
  the slot accepts any step or `Action([...])`, so `ShareButton("Ask", @ToAssistant("Hi"))` still
  sends a `continue_conversation` event.
</Callout>
