OpenUI Lang 1.0 extends the [v0.5 specification](/docs/openui-lang/specification-v05). The syntax stays the same. 1.0 adds a clear entry rule, custom functions and actions, single-step actions, a format for stored messages, and new error codes. See [What's New in 1.0](/docs/openui-lang/whats-new) for upgrade notes.

## Syntax Overview

A program is a list of **assignment statements**, one per line:

```text
identifier = Expression
```

The statement kinds are the same as in v0.5: component or value statements, `$variable` declarations, and `Query` or `Mutation` statements. 1.0 adds these expression forms:

| Form          | Syntax            | Example                                |
| ------------- | ----------------- | -------------------------------------- |
| Function call | `@Name(args)`     | `@Percent(done, total)`                |
| Action step   | `@Step(args)`     | `@ToAssistant("Tell me more")`         |
| Action        | `Action([steps])` | `Action([@Run(save), @Reset($title)])` |

All other expressions and operators work as in v0.5.

## Core Rules

1. **One statement per line:** `identifier = Expression`
2. **Entry:** the statement named `root`. See [Entry Statement](#entry-statement).
3. **Positional arguments:** mapped to props, function params, and action params by Zod key order. `null` skips an optional argument.
4. **Forward references allowed:** a statement can use a name defined later.
5. **`@` is required** for functions and steps. `Count(x)` is not a call. Only `Action([...])` works without the `@`.
6. **Last definition wins:** if two statements share a name, the later one is used.

## Entry Statement

The entry is the statement named `root`. Its value must be a component: a call, a reference to one, or an expression that gives one.

```text
$compact = false
root = $compact ? compactView : fullView
compactView = TextContent("3 open")
fullView = Card([TextContent("3 open tickets")])
```

With no `root` statement, the client looks at the first statement that is not a `$variable`, `Query`, or `Mutation`. If it calls the library's root component, it is the entry. It renders, with a `no-root` warning:

```text
page = Card([title])
title = TextContent("Orders")
```

In every other case nothing renders, and `no-root` is reported when the stream ends. While streaming, a missing entry is not an error.

## Function Calls

`@Name(args)` calls a built-in function or a custom function from the library. The built-ins are the same as in v0.5. Built-ins are looked up first, and a library cannot reuse a built-in or step name.

Custom function arguments are checked like component props:

- A literal argument with the wrong type, or a required one that is missing or `null`, makes the call `null`. The error is `type-mismatch`, `missing-required`, or `null-required`.
- A wrong optional argument is dropped and its default applies. Extra arguments report `excess-args` and are dropped.
- A required argument that is `null` at runtime, such as an unset `$variable`, makes the call `null` with no error.
- A wrong runtime type, a function that throws, or a result that does not match `returns` reports `runtime-error`. The call is `null`.

Custom functions must be pure and synchronous. The client may call them any number of times, in any order.

A call to an `@Name` that is not a built-in, a step, or a library function reports `unknown-function` and evaluates to `null`. The rest of the statement still renders:

```text
root = Card([total])
total = TextContent("Total: " + @Total(items))
```

See [Functions](/docs/openui-lang/functions).

## Action Expressions

One step needs no wrapper. Several steps go in `Action([...])` and run in order:

```text
askBtn = Button("Tell me more", @ToAssistant("Tell me more about this order"))
saveBtn = Button("Save", Action([@Run(save), @Run(orders), @Reset($note)]))
```

`@ToAssistant("Hi")` is the same as `Action([@ToAssistant("Hi")])`. A nested `Action([...])` is flattened. A plain list of steps, such as `[@Set($a, 1), @ToAssistant("Hi")]`, is not an action. It is plain data, with no error.

### Steps

| Step                              | Description                                                                 |
| --------------------------------- | --------------------------------------------------------------------------- |
| `@ToAssistant(message, context?)` | Send a `continue_conversation` event. `context` can be any value            |
| `@OpenUrl(url)`                   | Send an `open_url` event                                                    |
| `@Set($var, value)`               | Set a `$variable`. `value` is evaluated when the step runs                  |
| `@Reset($var1, $var2)`            | Restore `$variables` to declared defaults                                   |
| `@Run(ref)`                       | Run a Mutation or re-fetch a Query. A failed mutation stops the later steps |
| `@Name(args)`                     | A custom action. Sends an event with `type: "Name"` and `params`            |

The `context` of `@ToAssistant` reaches the host unchanged in `params.context`:

```text
approveBtn = Button("Approve", @ToAssistant("Approve this order", {orderId: 42}))
```

Each event carries the form state as of when its step runs.

### Invalid steps

A step that cannot run does nothing, and the other steps still run. A custom action with any invalid argument, required or optional, is a no-op. It does not fall back to a default.

Only an `@Name(...)` call written in the program creates a custom step. An object, a `$variable`, or a query row shaped like a step never reaches the host as one.

### Restricted action slots

A prop can accept only some steps. The prompt prints it with the step names:

```text
ShareButton(label: string, share: @CopyToClipboard | @OpenUrl)
```

In the JSON Schema, the prop is an `anyOf` of `$ref`s to the step names. A prop that takes any action is `{"$ref": "#/$defs/ActionExpression"}`. In 1.0 the restriction shapes the prompt and the schema only. At runtime the slot accepts any action.

See [Actions](/docs/openui-lang/actions).

## Stored Messages

A host stores a response as text, with marker lines that start with `]]>openui:`. The model never writes or sees them.

```text
]]>openui:content?library=support%401.2.0
root = Card([title])
title = TextContent("Order 42")
]]>openui:context
{"formState":{"note":"rush"}}
]]>openui:end
```

| Line                | Meaning                                               |
| ------------------- | ----------------------------------------------------- |
| `]]>openui:content` | Starts the program, or prose with fenced programs     |
| `]]>openui:context` | Starts host data, such as form state. Usually JSON    |
| `]]>openui:end`     | The stream finished. A message without it was cut off |

A marker counts only at the start of a line. With several `content` sections, the last one wins. Text with no markers is the content. A message with no `end` line still renders. See [Message Protocol](/docs/openui-lang/message-protocol).

## Error Codes

| Code                | Meaning                                                  | Result                              |
| ------------------- | -------------------------------------------------------- | ----------------------------------- |
| `unknown-component` | Component not in the library                             | Component dropped                   |
| `missing-required`  | Required prop or param missing                           | Default if any, else dropped        |
| `null-required`     | Required prop or param is `null`                         | Same as `missing-required`          |
| `type-mismatch`     | Wrong type, enum value, or data in a component-only slot | Default if any, else dropped        |
| `excess-args`       | More arguments than props or params                      | Extras dropped, still renders       |
| `inline-reserved`   | `Query` or `Mutation` used inline                        | Evaluates to nothing                |
| `unknown-function`  | `@Name` is not a built-in, step, or library function     | Call is `null`, statement kept      |
| `no-root`           | No usable entry                                          | Warning with the fallback, or fatal |
| `parse-failed`      | Text with no statements                                  | Fatal                               |
| `runtime-error`     | Evaluation or a function call failed                     | The prop or call is `null`          |

`unknown-function` and `no-root` are new in 1.0. Query, mutation, and render errors are as in the [Renderer](/docs/openui-lang/renderer) docs.

An error with `severity: "warning"` did not stop the page from rendering. Today that is the `no-root` fallback. Skip warnings when you send errors back to the model.

## Prompt Feature Flags

The flags are the same as in v0.5, plus `builtinFunctions`. It lists the built-in functions in a library without `toolCalls` or `bindings`. A library's own functions and actions are always listed. See [System Prompts](/docs/openui-lang/system-prompts).

## Streaming

Forward references and hoisting work as in v0.5. When the stream ends, the result equals a parse of the full text: statements, entry, errors, and state defaults.
