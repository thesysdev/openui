---
title: Custom Functions
description: Add your own @-prefixed functions to a library with defineFunction.
---

A library can add its own functions next to the [built-ins](/docs/openui-lang/builtins). The model calls them with an `@` prefix, like `@Count`, and the renderer runs your implementation on the client. Use them for formatting and small calculations that the model should not do by hand.

## Define a function

```tsx
import { createLibrary, defineComponent, defineFunction } from "@openuidev/react-lang";
import { z } from "zod/v4";

const percent = defineFunction({
  name: "Percent",
  description: "Formats part / total as a percentage",
  params: z.object({
    part: z.number(),
    total: z.number().default(100),
  }),
  returns: z.string(),
  fn: ({ part, total }) => `${((part / total) * 100).toFixed(1)}%`,
});

const TextContent = defineComponent({
  name: "TextContent",
  description: "A line of text",
  props: z.object({ text: z.string() }),
  component: ({ props }) => <p>{props.text}</p>,
});

export const library = createLibrary({
  root: "TextContent",
  components: [TextContent],
  functions: [percent],
});
```

The model can now write:

```text
root = TextContent("Done: " + @Percent(42, 120))
```

This renders "Done: 35.0%".

To add a function to an existing library, such as `openuiLibrary` from `@openuidev/react-ui`, use [`library.extend`](/docs/openui-lang/extending-libraries).

## Fields

| Field         | Description                                                                                    |
| :------------ | :--------------------------------------------------------------------------------------------- |
| `name`        | The name after `@` in programs. Start it with an uppercase letter, like the built-ins.         |
| `description` | Shown next to the signature in the prompt.                                                     |
| `params`      | A `z.object(...)`. Key order is the positional order of the arguments.                         |
| `returns`     | Optional. A Zod schema for the result. It is printed in the prompt and checked at runtime.     |
| `fn`          | The implementation. It receives one object keyed by the `params` names, with defaults applied. |

`params` must be a `z.object(...)`. Anything else throws when you call `defineFunction`.

## In the prompt

The prompt lists custom functions in its "Built-in Functions" section, after the built-ins. The line for `@Percent` starts with this signature, followed by the description:

```text
@Percent(part: number, total?: number) → string
```

A param with `.optional()` or `.default(...)` prints with `?`. The return type comes from `returns`. Without `returns`, the signature has no `→` part.

The section is printed whenever the library has functions, because they also work in plain props. The built-in functions are listed only when `toolCalls` or `bindings` is on. Set the `builtinFunctions` prompt option to list them in a static library too:

```ts
const systemPrompt = library.prompt({ builtinFunctions: true });
```

`library.toSpec()` includes each function's signature and description, and `library.toJSONSchema()` includes its `params` and `returns` as JSON Schema under `functions`. The spec file written by `openui generate` therefore carries them to `generateSystemPrompt` on your backend. Only the client needs `fn`.

## Arguments

Arguments are positional, in the key order of `params`, the same rule as component props. `fn` receives them as one object:

| Call                 | `fn` receives              |
| :------------------- | :------------------------- |
| `@Percent(42, 120)`  | `{ part: 42, total: 120 }` |
| `@Percent(42)`       | `{ part: 42, total: 100 }` |
| `@Percent(42, null)` | `{ part: 42, total: 100 }` |

A missing optional argument, or `null` in its place, takes the param's default. An optional param with no default is left out of the object.

## Validation

Arguments go through the same checks as component props, so a mistake in one call does not break the page.

Literal arguments are checked when the program is parsed:

| Problem                          | Error code                            | Result                                           |
| :------------------------------- | :------------------------------------ | :----------------------------------------------- |
| Wrong type for a required param  | `type-mismatch`                       | The call evaluates to `null`.                    |
| Required param missing or `null` | `missing-required` or `null-required` | The call evaluates to `null`.                    |
| Wrong type for an optional param | `type-mismatch`                       | The argument is dropped and the default applies. |
| More arguments than params       | `excess-args`                         | The extra arguments are dropped. The call runs.  |

Arguments that are only known at runtime (a `$variable`, a reference, a query result, an expression) are checked when the call runs:

- A required argument that is `null` or missing, with no default, makes the call evaluate to `null` with no error. This covers an unset `$variable` or a query that has not returned yet.
- A required argument of the wrong type reports `runtime-error`, and the call evaluates to `null`.
- An optional argument of the wrong type reports `runtime-error`, and its default applies. The call runs.
- If `fn` throws, the call reports `runtime-error` (`@Percent threw: ...`) and evaluates to `null`.
- If the result does not match `returns`, the call reports `runtime-error` and evaluates to `null`. Without `returns`, the result is used as is.

The React `Renderer` sends these errors to `onError` once the stream has ended.

Custom actions are stricter. Any invalid argument there, optional or not, makes the step a no-op. See [Custom Actions](/docs/openui-lang/custom-actions#invalid-arguments).

## When functions run

The client evaluates function calls, not the model:

- on every streamed chunk, including the statement that is still arriving, so a number that is still being typed can give an intermediate result;
- again whenever a value the call reads changes, such as a `$variable`, a query result, or a referenced statement.

```text
$done = 3
root = Stack([progress, addBtn])
progress = TextContent("Progress: " + @Percent($done, 10))
addBtn = Button("Add one", @Set($done, $done + 1))
```

Clicking the button updates `$done`, and the text changes from "Progress: 30.0%" to "Progress: 40.0%" without a call to the model.

Because the runtime may call `fn` many times and in any order, keep it pure and synchronous: the same inputs give the same output, with no state, network, or clock access. For side effects, use a [custom action](/docs/openui-lang/custom-actions).

## Built-ins use the same definition

The built-in functions are defined with `defineFunction` inside `@openuidev/lang-core`, so their prompt lines are generated the same way:

```text
@Sum(numbers: number[]) → number
@Round(number: number, decimals?: number) → number
@Filter(array: any[], field: string, operator: "==" | "!=" | ">" | "<" | ">=" | "<=" | "contains", value: any) → any[]
```

One difference: built-ins convert their arguments instead of validating them. `@Sum(["1", 2])` gives `3`.

`BUILTINS` (the built-in definitions by name) and `isBuiltin(name)` are exported from `@openuidev/lang-core`.

## Reserved names

`createLibrary` throws when a function name is already taken:

- a built-in function: `Count`, `First`, `Last`, `Sum`, `Avg`, `Min`, `Max`, `Sort`, `Filter`, `Round`, `Abs`, `Floor`, `Ceil`, `Each`;
- an action step or `Action`: `Run`, `ToAssistant`, `OpenUrl`, `Set`, `Reset`, `Action`;
- `Query` or `Mutation`;
- a component, another function, or a custom action in the same library.

```text
[createLibrary] Function "Sum" collides with a built-in, component, function, or action of the same name. Rename it.
```

A library cannot replace a built-in. Built-ins added in later releases become reserved too, so prefer specific names such as `FormatCurrency` over generic ones.

## Unknown functions

A call to an `@Name` that is not a built-in, an action step, or a library function reports `unknown-function` and evaluates to `null`. The rest of the statement still renders:

```text
root = TextContent("Total: " + @Total(items))
```

If the library has no `Total` function, this renders "Total: ".

## Renderer support

Custom functions run in the React `Renderer` from `@openuidev/react-lang`. The Vue, Svelte, and Angular renderers do not run them yet. Parsers built from `library.toJSONSchema()`, including Autofix in `@openuidev/server`, accept the calls.
