---
title: Entry Statement
description: Which statement a program renders from, and what happens when there is no root.
---

Rendering starts at one statement, the entry. Everything the entry reaches renders. A statement that nothing reaches is not rendered.

## The rule

1. **`root`.** The statement named `root` is the entry. Its value must evaluate to a component: a component call, a reference to one, or an expression that picks one.
2. **Fallback.** With no `root` statement, look at the first statement that is not a `$variable`, `Query`, or `Mutation` declaration. If it calls the library's root component, it is the entry. It renders, and the parser reports `no-root` as a warning.
3. **No entry.** Otherwise nothing renders, and the parser reports `no-root` as an error.

The library's root component is the `root` you pass to `createLibrary`:

```ts
const library = createLibrary({ root: "Card", components: [Card, TextContent] });
```

The generated prompt still tells the model to start every program with `root = Card(...)`. The fallback only rescues programs where the model named that statement something else.

## Examples

These examples use a library whose root component is `Card`.

A `root` statement:

```text
root = Card([title])
title = TextContent("Orders")
```

Renders, with no error.

An entry that picks a component at runtime:

```text
$compact = false
root = $compact ? compactView : fullView
compactView = TextContent("3 orders")
fullView = Card([TextContent("Orders"), TextContent("3 open")])
```

Renders `fullView`, and switches to `compactView` when `$compact` becomes true.

No `root`, and the first statement after the declarations calls `Card`:

```text
$days = "7"
page = Card([title])
title = TextContent("Orders")
```

Renders `page`, with a `no-root` warning: `No root statement. Rendering the first statement, which calls the root component Card`.

No `root`, and the first statement is something else:

```text
title = TextContent("Orders")
page = Card([title])
```

Nothing renders. The `no-root` error says `No root statement, and the first statement does not call the root component Card`.

A `root` that is not a component:

```text
root = "Orders"
```

Nothing renders. The `no-root` error says `root does not evaluate to a component`.

## Notes

- If the library has no `root`, only a statement named `root` can be the entry.
- While a response streams, a missing entry is not an error. The React `Renderer` reports `no-root` when the stream ends.
- A program whose `root` statement comes last shows nothing while it streams, until the `root` line arrives. Write `root` first, as the generated prompt asks.
- An output cut off before its `root` statement, for example at the token limit, renders blank instead of a partial tree.
- The React `Renderer` reports `no-root` instead of `parse-failed` when the response has statements but no entry rendered.
- When there is no entry, `ParseResult.meta.orphaned` is empty. Nothing is reachable, and `no-root` describes the problem.

## Warnings in `onError`

Errors now carry an optional `severity`. The fallback entry reports `no-root` with `severity: "warning"`, because the page still rendered. If you send errors back to the model for a fix, skip warnings:

```tsx
<Renderer
  library={library}
  response={response}
  onError={(errors) => {
    const fixable = errors.filter((e) => e.severity !== "warning");
    if (fixable.length) requestFix(fixable);
  }}
/>
```

Autofix in `@openuidev/server` already ignores warnings.

## Entries that pick a component

When `root` is an expression such as `$compact ? compactView : fullView`, the parser cannot pick the component ahead of time. `ParseResult.root` is `null`, and `ParseResult.rootExpression` holds the expression. The React `Renderer` evaluates it for you. A custom renderer built on `@openuidev/lang-core` calls `evaluateRoot()` to get the component.

The Vue, Svelte, and Angular renderers apply the entry rule and report the same errors, but do not render these entries yet.

## Changes from 0.5

Before 1.0, a program without `root` rendered its first component statement, or a later statement that called the root component. Now only the first statement after the declarations can stand in for `root`, and only when it calls the root component. In our benchmark corpus, 151 of 24,423 programs (0.6%) stop rendering because of this.
