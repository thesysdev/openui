Configure one client for [Autofix](/docs/gateway/api/autofix) and message persistence. Import from the path matching your model SDK.

## Install

```bash tab="pnpm" tab-group="pkg"
pnpm add @openuidev/server
```

```bash tab="bun" tab-group="pkg"
bun add @openuidev/server
```

```bash tab="yarn" tab-group="pkg"
yarn add @openuidev/server
```

```bash tab="npm" tab-group="pkg"
npm install @openuidev/server
```

## Import paths

| Import                     | Client capabilities                                   |
| -------------------------- | ----------------------------------------------------- |
| `@openuidev/server/openai` | `autofix.completions`, `conversations.appendMessages` |
| `@openuidev/server/vercel` | `autofix.ai`                                          |

## `createServerClient(options?)`

```ts tab="OpenAI" tab-group="server-sdk"
import { createServerClient } from "@openuidev/server/openai";

const openui = createServerClient();
```

```ts tab="Vercel AI SDK" tab-group="server-sdk"
import { createServerClient } from "@openuidev/server/vercel";

const openui = createServerClient();
```

The client reads `process.env.THESYS_API_KEY` by default. Explicit options take precedence. A missing or empty key throws `ServerClientError` with `code: "missing_api_key"` at creation. Keep the key on the server.

```ts
interface ServerClientOptions {
  apiKey?: string;
  apiBaseUrl?: string; // Gateway origin, without /v1. Default: https://api.thesys.dev.
  fetch?: typeof globalThis.fetch;
}
```

Libraries, conversation IDs, and abort signals belong to individual operations. The client can be reused across requests.

## Autofix

Use the spec from `openui generate --spec` for the same library as your renderer, including its `schema`.

### `autofix.completions.fix(input)`

Validate completed OpenUI text locally and request repair only when invalid. The Vercel client's `autofix.ai.fix` has the same completed-text contract.

```ts
import library from "./openui.spec.json";

const result = await openui.autofix.completions.fix({
  library,
  generation,
  messages,
  signal,
});

if (result.content !== null) {
  // Render or persist result.content.
} else {
  console.warn(result.unfixedErrors);
}
```

| Input        | Purpose                                                                    |
| ------------ | -------------------------------------------------------------------------- |
| `library`    | Required library spec with schema.                                         |
| `generation` | Required completed OpenUI text.                                            |
| `messages`   | Optional repair context in Chat Completions format, before the generation. |
| `signal`     | Optional cancellation signal.                                              |

```ts
type AutofixResult = {
  original: string;
  fixedErrors: AutofixDiagnostic[];
  unfixedErrors: AutofixDiagnostic[];
} & (
  { status: "already_valid" | "fixed"; content: string } | { status: "fix_failed"; content: null }
);

interface AutofixDiagnostic {
  code: string;
  message: string;
  component?: string;
  path?: string;
  statementId?: string;
}
```

### `autofix.completions.stream(input)`

Wrap a native Chat Completions stream. The client preserves provider events and inserts any correction before successful completion.

```ts
const source = await model.chat.completions.create(
  { model: "gpt-5.5", messages, stream: true },
  { signal: request.signal },
);

return openui.autofix.completions
  .stream({ library, stream: source, messages, signal: request.signal })
  .toResponse();
```

Pair the response with the frontend `openAIAdapter()`.

### `autofix.ai.stream(input)`

The Vercel client accepts AI SDK UI message events, rather than raw model events:

```ts
import { streamText, toUIMessageStream } from "ai";
import { createServerClient } from "@openuidev/server/vercel";

const openui = createServerClient();
const result = streamText({
  model: "openai/gpt-5.5",
  system: systemPrompt,
  prompt: "Show a greeting card",
  abortSignal: signal,
});

return openui.autofix.ai
  .stream({
    library,
    stream: toUIMessageStream({ stream: result.stream }),
    signal,
  })
  .toResponse();
```

`toResponse()` uses the UI message SSE protocol consumed by `useChat`.

### Stream consumption and errors

All stream methods take `library`, `stream`, optional `messages`, and optional `signal`. The source is an `AsyncIterable` of the selected provider's native events, optionally with an abort controller.

```ts
interface AutofixStream<T> {
  chunks: AsyncIterable<T>;
  toResponse(): Response;
  result: Promise<AutofixResult | null>;
}
```

Use either `chunks` or `toResponse()` once. `result` settles after consumption and is `null` when Autofix validation did not run. Persist settled `result.content` when present, rather than joined deltas.

| Autofix error code     | Meaning                                                          |
| ---------------------- | ---------------------------------------------------------------- |
| `invalid_library`      | Library schema is missing.                                       |
| `generation_too_large` | Generation exceeds 100,000 characters.                           |
| `http_error`           | Repair request failed; `status` is set.                          |
| `invalid_response`     | Repair response could not be read.                               |
| `stream_consumed`      | The stream was consumed more than once.                          |
| `fix_failed`           | Streamed output could not be repaired; diagnostics are attached. |

## Conversation history

### `conversations.appendMessages(input)`

Currently accepts **Chat Completions messages only**. User and assistant messages, function calls, and tool results become Conversations API items. System and developer messages are skipped. An empty converted turn makes no request.

```ts
await openui.conversations.appendMessages({
  conversationId: threadId,
  messages: [
    { role: "user", content: lastUserText },
    { role: "assistant", content: correctedAssistantText },
  ],
  signal,
});
```

```ts
interface AppendMessagesInput {
  conversationId: string;
  messages: ChatCompletionMessageParam[];
  signal?: AbortSignal;
}
```

Returns a `ConversationItemList`. The conversation must already exist. Pass only the new turn, not full replay; replay duplicates items. Writes are not retried automatically. Responses generation using `conversation` and `store: true` already persists its turn and must not append it again.

## Deprecated helpers

`createAutofix`, `storeChatCompletionHistory`, and `chatCompletionMessagesToItems` remain exported for compatibility and are marked deprecated.

| Previous call                                                      | Client replacement                                                  |
| ------------------------------------------------------------------ | ------------------------------------------------------------------- |
| `createAutofix({ apiKey, library }).completions.fix(input)`        | `openui.autofix.completions.fix({ ...input, library })`             |
| `createAutofix({ apiKey, library }).completions.stream(input)`     | `openui.autofix.completions.stream({ ...input, library })`          |
| Vercel `createAutofix({ apiKey, library }).ai.stream(input)`       | `openui.autofix.ai.stream({ ...input, library })`                   |
| `storeChatCompletionHistory({ apiKey, conversationId, messages })` | `openui.conversations.appendMessages({ conversationId, messages })` |

Provider entry points export their inferred `ServerClient` type, `ServerClientOptions`, `ServerClientError`, Autofix input/result types, and `AutofixError`. The OpenAI entry point exports `AppendMessagesInput`.
