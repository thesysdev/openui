Server utilities for OpenUI Gateway. Validate and repair model-generated OpenUI Lang, and persist a completed turn as Conversations API items. Both live on `OpenUIClient`; Autofix calls the [Autofix HTTP API](/docs/autofix).



## The client

Import everything from `@openuidev/server`. Create the client once, on your server. It reads your API key from `THESYS_API_KEY` unless you pass `apiKey`.

```ts
import { OpenUIClient } from "@openuidev/server";

const openui = new OpenUIClient();
```

## `createAutofix(params)`

Creates the Autofix helpers for your SDK: `openui.chat.createAutofix` for Chat Completions, `openui.ai.createAutofix` for the Vercel AI SDK. Use the spec from `openui generate --spec` for the same library as your renderer, including its `schema`.

```ts tab="OpenAI" tab-group="autofix-sdk"
import library from "./openui.spec.json";

const autofix = openui.chat.createAutofix({ library });
```

```ts tab="Vercel AI SDK" tab-group="autofix-sdk"
import library from "./openui.spec.json";

const autofix = openui.ai.createAutofix({ library });
```

```ts tab="Non-streaming" tab-group="autofix-sdk"
import library from "./openui.spec.json";

const autofix = openui.chat.createAutofix({ library });
// const autofix = openui.ai.createAutofix({ library });
```

```ts
openui.chat.createAutofix(params: {
  library: LibrarySpec & { schema: LibraryJSONSchema };
}): { fix; stream };

openui.ai.createAutofix(params: {
  library: LibrarySpec & { schema: LibraryJSONSchema };
}): { fix; stream };
```

Requests use the client's API key, `baseUrl` and `fetch`. Pair each stream with the matching frontend adapter: `openAIAdapter()` or `useChat`.

## `fix(input)`

Validate completed OpenUI text. Valid output is returned as-is. Invalid output is sent to `POST /v1/autofix`.

```ts
const result = await autofix.fix({ generation, messages, signal });

if (result.content !== null) {
  // already_valid or fixed — use result.content
} else {
  // fix_failed — choose a fallback
  console.warn(result.unfixedErrors);
}
```

```ts
function fix(input: {
  generation: string;
  messages?: ChatCompletionMessageParam[];
  signal?: AbortSignal;
}): Promise<AutofixResult>;
```

`generation` is the completed OpenUI text. Optional `messages` is the conversation before that generation. On `fixed`, `content` is the program the Autofix API returned.

```ts
type AutofixResult = {
  original: string;
  fixedErrors: AutofixDiagnostic[];
  unfixedErrors: AutofixDiagnostic[];
} & (
  { status: "already_valid" | "fixed"; content: string } | { status: "fix_failed"; content: null }
);

interface AutofixDiagnostic {
  code: string;
  message: string;
  component?: string;
  path?: string;
  statementId?: string;
}
```

## `stream(input)`

Wrap a native SDK stream. The helper forwards provider events and inserts a repair before the stream completes when the finished UI is invalid.

```ts
function stream(input: {
  stream: AsyncIterable<Chunk> & { controller?: AbortController };
  messages?: ChatCompletionMessageParam[];
  signal?: AbortSignal;
}): AutofixStream<Chunk>;
```

From `openui.chat`, pass a native Chat Completions stream. From `openui.ai`, pass `toUIMessageStream({ stream: result.stream })`, not the raw `result.stream`.

```ts
interface AutofixStream<T> {
  chunks: AsyncIterable<T>;
  toResponse(): Response;
  result: Promise<AutofixResult | null>;
}
```

Use either `chunks` or `toResponse()` once. `result` settles after that consumer finishes. Persist `result.content` when it is a string — that is the Autofix program, not the joined stream text. `result` is `null` when Autofix did not run.

```ts title="app/api/chat/route.ts" tab="OpenAI" tab-group="autofix-sdk"
import OpenAI from "openai";
import { OpenUIClient } from "@openuidev/server";
import library from "./openui.spec.json";

const model = new OpenAI();
const autofix = new OpenUIClient().chat.createAutofix({ library });

export async function POST(request: Request) {
  const { messages } = await request.json();
  const source = await model.chat.completions.create(
    { model: "openai/gpt-5.5", messages, stream: true },
    { signal: request.signal },
  );

  return autofix.stream({ stream: source, messages, signal: request.signal }).toResponse();
}
```

```ts title="app/api/chat/route.ts" tab="Vercel AI SDK" tab-group="autofix-sdk"
import { streamText, toUIMessageStream } from "ai";
import { OpenUIClient } from "@openuidev/server";
import library from "./openui.spec.json";

const autofix = new OpenUIClient().ai.createAutofix({ library });

const result = streamText({
  model: "openai/gpt-5.5",
  system: systemPrompt,
  prompt: "Show a greeting card",
  abortSignal: signal,
});

return autofix
  .stream({
    stream: toUIMessageStream({ stream: result.stream }),
    signal,
  })
  .toResponse();
```

```ts title="server.ts" tab="Non-streaming" tab-group="autofix-sdk"
const result = await autofix.fix({ generation, messages, signal });

if (result.content !== null) {
  // already_valid or fixed — use result.content
} else {
  console.warn(result.unfixedErrors);
}
```

```ts tab="OpenAI" tab-group="autofix-sdk"
const output = autofix.stream({ stream: source, messages, signal });

for await (const chunk of output.chunks) {
  // Native SDK events, including any appended correction
}

const settled = await output.result;
if (settled?.content) {
  // Persist settled.content
}
```

```ts tab="Vercel AI SDK" tab-group="autofix-sdk"
const output = autofix.stream({
  stream: toUIMessageStream({ stream: result.stream }),
  signal,
});

for await (const chunk of output.chunks) {
  // Native SDK events, including any appended correction
}

const settled = await output.result;
if (settled?.content) {
  // Persist settled.content
}
```

```ts tab="Non-streaming" tab-group="autofix-sdk"
if (result.content) {
  // Persist result.content
}
```

A failed repair on a stream throws with `code: "fix_failed"`. Use `fix()` on the same helper when you already have completed text.

### Errors

Autofix throws `AutofixError`, exported from `@openuidev/server`, with a `code` string:

| `code`                 | When                                               |
| :--------------------- | :------------------------------------------------- |
| `missing_api_key`      | No API key: pass `apiKey` or set `THESYS_API_KEY`  |
| `invalid_library`      | `library.schema` is missing                        |
| `generation_too_large` | Generation exceeds 100,000 characters              |
| `http_error`           | Autofix HTTP request failed (`status` is set)      |
| `invalid_response`     | Autofix response could not be read                 |
| `stream_consumed`      | `chunks` or `toResponse()` was used more than once |
| `fix_failed`           | Streamed generation could not be repaired          |

## Conversation history

Store each turn in an OpenUI Cloud conversation, and read the thread back for the next request, in your SDK's messages, with the same `openui` client.

- `openui.chat.conversations` takes and returns Chat Completions messages. Its types come from the optional `openai` peer.
- `openui.langgraph.conversations` takes LangChain messages. Its types come from the optional `@langchain/core` peer.

Calls go by id with your API key, as your org. Before acting on a conversation id from the browser, `get` it and check its `userId` is the signed-in user, taken from your session. `create` names the owner; if your frontend tokens carry an app id, pass the same `appId` to `new OpenUIClient()`.

### `items.create(id, messages, options?)`

Store the new turn. Earlier messages are already stored, so passing the full history duplicates them.

```ts tab="Chat Completions" tab-group="history-sdk"
await openui.chat.conversations.items.create(threadId, [
  { role: "user", content: lastUserText },
  { role: "assistant", content: assistantText },
]);
```

```ts tab="LangGraph" tab-group="history-sdk"
const { messages } = await graph.invoke({ messages: [...history, new HumanMessage(text)] });

await openui.langgraph.conversations.items.create(threadId, messages.slice(history.length));
```

```ts
function create(
  id: string,
  messages: readonly ChatCompletionMessageParam[], // LangGraph: readonly BaseMessage[]
  options?: { signal?: AbortSignal },
): Promise<ConversationItem[]>;
```

- System and developer messages are skipped.
- A tool call is stored only together with its result, so a turn stopped mid tool call leaves the thread valid for the next request.
- It resolves with the items as stored. With nothing to store, it resolves with `[]` and sends no request.

### `items.list(id, options?)`

Read the whole thread, oldest first, ready to send to the model. It reads every page.

```ts tab="Chat Completions" tab-group="history-sdk"
const history = await openui.chat.conversations.items.list(threadId);

const completion = await client.chat.completions.create({
  model,
  messages: [systemMessage, ...history, userMessage],
});
```

```ts tab="LangGraph" tab-group="history-sdk"
const history = await openui.langgraph.conversations.items.list(threadId);

await graph.invoke({ messages: [...history, new HumanMessage(text)] });
```

```ts
function list(
  id: string,
  options?: { signal?: AbortSignal },
): Promise<ChatCompletionMessageParam[]>; // LangGraph: Promise<LangGraphHistoryMessage[]>

type LangGraphHistoryMessage =
  | { role: "human"; content: MessageContent }
  | { role: "ai"; content: string; tool_calls?: ToolCall[] }
  | { role: "tool"; content: string; tool_call_id: string };
```

- User images come back as `image_url` parts. Other stored items, such as `reasoning`, are skipped.
- LangGraph messages are plain objects. `graph.invoke`, or `coerceMessageLikeToMessage` from `@langchain/core/messages`, turns them into LangChain messages.

### Conversation calls

Both namespaces also have the conversation calls of `openui.conversations`:

```ts
interface ConversationCalls {
  list(params?: {
    userId?: string;
    limit?: number;
    after?: string;
    before?: string;
  }): Promise<CloudConversationList>; // newest first; with userId, that user's in every app
  create(
    params: { title?: string; metadata?: Record<string, string> },
    options: { userId: string },
  ): Promise<CloudConversation>;
  get(id: string, options?: { signal?: AbortSignal }): Promise<CloudConversation>;
  update(
    id: string,
    params: { title?: string; metadata?: Record<string, string> },
    options?: { signal?: AbortSignal },
  ): Promise<CloudConversation>;
  delete(id: string, options?: { signal?: AbortSignal }): Promise<void>;
}

interface CloudConversation {
  id: string;
  title?: string;
  metadata?: Record<string, string>;
  userId?: string;
  appId?: string;
  createdAt: number; // ms
}

interface CloudConversationList {
  data: CloudConversation[];
  hasMore: boolean;
  firstId?: string;
  lastId?: string;
}
```

`create` requires `userId`, the owner: a conversation with no owner can't be read from the user's browser. `list` takes it to list only that user's conversations. Every call also takes `signal`.

### Converters

Convert without storing: `chatCompletionsConverter` and `langGraphConverter` are the conversions `openui.chat` and `openui.langgraph` use.

```ts
import { chatCompletionsConverter } from "@openuidev/server";

const items = chatCompletionsConverter.toItems(turn); // a turn as items to store
const messages = chatCompletionsConverter.fromItems(storedItems); // stored items, oldest first
```

```ts
abstract class ConversationItemConverter<Input, Output = Input> {
  toItems(messages: readonly Input[]): ConversationItemInput[];
  fromItems(items: readonly ConversationItem[]): Output[];
}

const chatCompletionsConverter: ConversationItemConverter<ChatCompletionMessageParam>;
const langGraphConverter: ConversationItemConverter<BaseMessage, LangGraphHistoryMessage>;
```

`toItems` skips system messages and unpaired tool calls, as `items.create` does. `fromItems` keeps a tool call only with its result.

### Errors

Failed calls throw `OpenUIApiError` with a `code` and the HTTP `status`:

- `404`: the conversation or item doesn't exist.
- `invalid_input`: `messages` isn't an array, or `userId` is empty.

## Exports

All from `@openuidev/server`.

| Export                                           | Description                                                            |
| :----------------------------------------------- | :--------------------------------------------------------------------- |
| `OpenUIClient`                                   | Autofix, `openui.chat.conversations`, `openui.langgraph.conversations` |
| `OpenUIApiError`                                 | Error with `code` and `status`                                         |
| `AutofixError`                                   | Autofix error with `code`, and `status` on `http_error`                |
| `AutofixResult`, `AutofixStream`                 | Types of `fix()` and `stream()` results                                |

| `ConversationItemConverter`                      | Type of the two converters                                             |
