---
title: Image Search API
description: Implement an image search tool for any model or agent framework.
---

The Image Search API returns images for a query, with the page that shows each image. Use it to implement an image search tool for any model or agent framework. The model calls your tool, your backend calls this endpoint, and the results go back to the model.

**Endpoint:** `POST https://api.thesys.dev/v1/search/images`

The endpoint is not OpenAI compatible, so call it with `fetch` or another HTTP client. Server calls use the API key described in [Authentication](/docs/gateway/authentication).

## Make a request

```ts title="lib/search-images.ts"
type ImageResult = { title: string; image_url: string; page_url: string };

export async function searchImages(query: string): Promise<{ results: ImageResult[] }> {
  const response = await fetch("https://api.thesys.dev/v1/search/images", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.THESYS_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ query, num_results: 5 }),
  });

  if (!response.ok) {
    throw new Error(`Image search failed: ${response.status}`);
  }

  return response.json();
}
```

## Request

| Field         | Type    | Required | Purpose                                            |
| ------------- | ------- | -------- | -------------------------------------------------- |
| `query`       | string  | Yes      | What to search images for, 1 to 2,048 characters   |
| `num_results` | integer | No       | How many images to return, from 1 to 10, default 5 |

## Read the result

`results` holds the matches, and can hold fewer than `num_results`. `usage.search_units` reports the searches charged, and is always 1.

| Field           | Type    | Always present | Content                                  |
| --------------- | ------- | -------------- | ---------------------------------------- |
| `title`         | string  | Yes            | The title of the image or its page       |
| `image_url`     | string  | Yes            | The URL of the image file                |
| `page_url`      | string  | Yes            | The URL of the page that shows it        |
| `source`        | string  | Yes            | The domain of that page                  |
| `width`         | integer | No             | The image width in pixels                |
| `height`        | integer | No             | The image height in pixels               |
| `thumbnail_url` | string  | No             | The URL of a smaller copy                |
| `mime_type`     | string  | No             | The image type, for example `image/jpeg` |

A search with one result:

```json
{
  "query": "golden gate bridge at night",
  "results": [
    {
      "title": "Golden Gate Bridge at night",
      "image_url": "https://images.example.com/ggb-night.jpg",
      "page_url": "https://example.com/san-francisco-at-night",
      "source": "example.com",
      "width": 1200,
      "height": 800,
      "thumbnail_url": "https://thumbs.example.com/ggb-night.jpg",
      "mime_type": "image/jpeg"
    }
  ],
  "usage": { "search_units": 1 }
}
```

## Use as a function tool

Declare the tool in your model request. This example uses the Chat Completions format. When the model calls the tool, run the search in your backend and return the output as the tool result. The loop is the same as for any other function tool. See [Function tools](/docs/gateway/api/chat-completions#function-tools).

```ts title="lib/search-images-tool.ts"
import { searchImages } from "./search-images";

export const searchImagesTool = {
  type: "function",
  function: {
    name: "search_images",
    description: "Find images on the web.",
    parameters: {
      type: "object",
      properties: { query: { type: "string", description: "What to search for" } },
      required: ["query"],
    },
  },
} as const;

export async function runSearchImages({ query }: { query: string }) {
  const { results } = await searchImages(query);

  return JSON.stringify(
    results.map(({ title, image_url, page_url }) => ({ title, image_url, page_url })),
  );
}
```

The output keeps the title, image URL, and page URL, so that the model can show each image and link to its page.

The Responses API can also run image search inside the Gateway, with no function tool. See [Hosted Tools](/docs/gateway/api/responses/hosted-tools).

## Data

The query you send is passed to a third-party search provider. The query and the results are not stored beyond the request logs.

## Pricing

Each successful call is charged a flat price from your credits, and does not use a plan API call. A call that finds no results is still charged. A failed call is free. See [Pricing](/docs/gateway/pricing-credits) for the current rate.

## Errors

The endpoint returns the same error shape as the Chat Completions and Responses APIs. For a `400`, `message` is a list of every problem.

| Status | Type                    | When                                                                                        |
| ------ | ----------------------- | ------------------------------------------------------------------------------------------- |
| `400`  | `invalid_request_error` | `query` is missing, empty, or longer than 2,048 characters, or `num_results` is not 1 to 10 |
| `401`  | `invalid_api_key`       | The API key is missing or invalid                                                           |
| `429`  | `rate_limit_error`      | The organization has no credits, has reached its spend limit, or billing is suspended       |
| `500`  | `internal_server_error` | The search provider failed, and nothing is charged                                          |
