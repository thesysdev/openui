---
title: Chat Completions
---

Gateway provides OpenAI compatible Chat Completions API endpoints, letting you use multiple AI providers through a familiar interface. You can use existing OpenAI client libraries, switch to Gateway with a URL change, and keep your current tools and workflows without code rewrites.

The Chat Completions API implements the same specification as the [**OpenAI Chat Completions API**](https://platform.openai.com/docs/api-reference/chat).

**Endpoint:** POST [https://api.thesys.dev/v1/embed/chat/completions](https://api.thesys.dev/v1/embed/chat/completions)

## Configure the client

```ts title="lib/gateway.ts"
import OpenAI from "openai";

export const gateway = new OpenAI({
  apiKey: process.env.THESYS_API_KEY,
  baseURL: "https://api.thesys.dev/v1/embed",
});
```

See [Authentication](/docs/gateway/authentication) before using the client in a server route.

## Generate OpenUI Lang

Configure the system message for OpenUI generation, then send the same messages shape used by the OpenAI SDK:

```ts title="server.ts"
import { generateSystemPrompt } from "@openuidev/lang-core";
import { gateway } from "./lib/gateway";
import library from "./openui.spec.json";

const completion = await gateway.chat.completions.create({
  model: "openai/gpt-5",
  messages: [
    { role: "system", content: generateSystemPrompt({ cloud: true, library }) },
    { role: "user", content: "Compare quarterly revenue by region." },
  ],
  stream: true,
});
```

The assistant message contains OpenUI Lang. When the request is configured for OpenUI generation, the Gateway validates and corrects that language while it streams.

## Plain text requests

The endpoint also supports ordinary model traffic. Send your own system prompt without OpenUI generation instructions, and the Gateway forwards a text-oriented request without applying OpenUI Lang correction.

```ts
const completion = await gateway.chat.completions.create({
  model: "anthropic/claude-sonnet-5",
  messages: [{ role: "user", content: "Summarize this support ticket." }],
});
```

Unknown providers can route through OpenRouter where supported. Use [Models](/docs/gateway/models) for the standard provider naming convention.

## Stream to an agent UI

Relay the server response without changing its SSE shape. In the browser, configure [Agent Interface adapters and message formats](/docs/agent/reference/adapters-and-formats) for the Chat Completions stream.

Chat Completions is message-based. Your application owns conversation history and sends the relevant `system`, `user`, `assistant`, and `tool` messages on every turn. You can explicitly save completed turns to OpenUI Cloud with the helper below, or use the [Responses API](/docs/gateway/api/responses) for automatic persistence.

## Function tools

Chat Completions returns function tool calls to the application; it does not execute them. Run the standard loop:

1. Send messages and function declarations.
2. Read `tool_calls` from the assistant message.
3. Execute each function in your application.
4. Append the assistant tool-call message and each tool result.
5. Continue until the model returns the final OpenUI Lang response.

## Save conversations to OpenUI Cloud

Chat Completions does not automatically save messages. You can keep its generation
API and explicitly append completed turns to OpenUI Cloud with
`storeChatCompletionHistory` from `@openuidev/server`.

Install it with `npm install @openuidev/server openai`. Create the conversation
first with `useOpenuiCloudStorage` or `POST /v1/conversations`, then pass its id
to the helper. Keep the API key on the server.

```ts title="server.ts"
import { storeChatCompletionHistory } from "@openuidev/server";
import type { ChatCompletionMessageParam } from "openai/resources/chat/completions";
import { gateway } from "./lib/gateway";

// Resolve these from your authenticated application state and saved history.
// Verify the conversation belongs to the current user before using the API key.
declare const conversationId: string;
declare const history: ChatCompletionMessageParam[];
const userMessage: ChatCompletionMessageParam = {
  role: "user",
  content: "Compare quarterly revenue by region.",
};

const completion = await gateway.chat.completions.create({
  model: "openai/gpt-5",
  messages: [...history, userMessage],
});
const choice = completion.choices[0];
if (!choice || choice.finish_reason !== "stop") {
  throw new Error("Finish the tool loop or handle the incomplete response before saving");
}

await storeChatCompletionHistory({
  apiKey: process.env.THESYS_API_KEY!,
  conversationId,
  messages: [userMessage, choice.message],
});
```

Pass **only the new turn**, including all assistant tool-call messages and their
tool results in order. Resending the full history duplicates previously saved
items. For streaming, assemble the completed messages and await the helper after
the model/tool loop finishes; do not save individual text deltas or interrupted
responses. Saving does not supply history to future model calls automatically.
After an ambiguous save failure, reload history before retrying: the append
endpoint is not idempotent.
