# `@openuidev/server`

One server client for OpenUI Gateway, with shared connection settings and request-specific library specs and messages.

## Create a client

```ts
import { createClient } from "@openuidev/server";

const client = createClient(); // Reads process.env.THESYS_API_KEY.
```

Explicit options override the environment:

```ts
const client = createClient({
  apiKey: "your-server-key",
  apiBaseUrl: "https://api.thesys.dev", // Gateway origin, without /v1.
  fetch: customFetch,
});
```

Keep the key on the server. Missing or empty keys throw `ServerClientError` with `code: "missing_api_key"`. The client can be reused across requests; libraries, conversation IDs, and abort signals are supplied per operation.

## Repair completed output

Completed-text repair is independent of the streaming provider:

```ts
import library from "./openui.spec.json";

const result = await client.autofix.fix({
  library,
  response: generatedOpenUI,
  messages, // Optional Chat Completions repair context, before this response.
  signal,
});
```

`response` is the completed OpenUI text string. Pass the library spec generated by `openui generate --spec`, including its `schema`. Autofix creates and caches its parser on the first use of each library object. It validates locally and contacts the repair endpoint only for invalid output.

Results have `status: "already_valid" | "fixed" | "fix_failed"`, `original`, `content`, `fixedErrors`, and `unfixedErrors`. `content` is null on repair failure; otherwise render or persist that complete value.

## Repair streaming output

```ts
const result = client.completions.autofix.stream({
  library,
  stream: completionEvents,
  messages,
  signal,
});
return result.toResponse();
```

For Vercel AI SDK UI message events:

```ts
return client.vercel.ai.autofix
  .stream({ library, stream: uiMessageEvents, messages, signal })
  .toResponse();
```

Use native provider events: Chat Completions pairs with frontend `openAIAdapter()`; AI SDK UI message events pair with `useChat`. Every streaming namespace takes `library`, `stream`, optional Chat Completions repair-context `messages`, and optional `signal`.

The stream exposes `chunks` (native events), `toResponse()` (HTTP output), and `result` (repair result or null if repair did not run). Consume either `chunks` or `toResponse()` once. `result` settles after consumption finishes. A failed streamed repair throws `AutofixError` with `code: "fix_failed"` and diagnostics.

## Append Completions messages

```ts
await client.completions.conversations.appendMessages({
  conversationId: threadId,
  messages: [
    { role: "user", content: lastUserText },
    { role: "assistant", content: correctedAssistantText },
  ],
  signal,
});
```

Accepts Chat Completions messages only and returns a `ConversationItemList`. It converts user/assistant messages and function calls/results into Conversations API items; system/developer instructions are skipped. An empty converted turn makes no request. The conversation must already exist. Append only the new turn to avoid duplicate items; writes are not retried automatically.

## Existing APIs

Existing provider imports and standalone helpers remain available with their signatures and behavior:

```ts
import {
  createAutofix,
  storeChatCompletionHistory,
  chatCompletionMessagesToItems,
} from "@openuidev/server/openai";
import { createAutofix as createVercelAutofix } from "@openuidev/server/vercel";

createAutofix({ apiKey, library }).completions.fix({ generation, messages, signal });
createVercelAutofix({ apiKey, library }).ai.stream({ stream, messages, signal });
await storeChatCompletionHistory({ apiKey, conversationId, messages });
chatCompletionMessagesToItems(messages);
```

The standalone helpers are marked deprecated but continue to work. New integrations can use the root `createClient` API: move `library` from initialization into each operation, replace completed `generation` with `response`, and use `client.completions.conversations.appendMessages` for existing persistence.

`ServerClientError` exposes `code` and optional HTTP `status`. Autofix keeps `AutofixError` and its existing domain results. The root exports `Client`, `ClientOptions`, `ClientFixInput`, `ClientAutofixStreamInput`, `AppendMessagesInput`, `AutofixResult`, and `AutofixStream` types.
